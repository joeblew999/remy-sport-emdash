# 2026-10-06 — What is left on the Remy-Sport site

**Status:** active — **0 of 5 done**. The only open plan here. The two plans that got the site this
far are in [`done/`](done/) as the record of why it is built the way it is; their ticks were never
kept up, so read this file, not them, for what is left.

## Where the site stands

Built and reviewed, running locally, deployed nowhere: pages and a blog from the CMS, a page per
event and per organisation read from the app, an edge cache, a sitemap, structured data. A hostile
review found no page that names a person. The app's entries are test data, so those pages carry a
"sample data" notice and stay out of search engines until `APP_DATA_IS_REAL` is switched on.

## Items

- [ ] **1. Every language the app speaks, without a copy of the site per language** — the site was
  built for English and Thai by hand: a second tree of routes under `src/pages/th/` and a strings
  file with two columns. The app ships 27 languages, and EmDash already does this work
  - [x] the language list is the app's (`project.inlang/settings.json` in `remy-sport`), in one
    place in `astro.config.mjs`, with English as the fallback for each. Proof: 27 codes, the
    same 27 as the app's; `src/i18n/ui.ts` reads them back from the config and lists none.
    All 27 are codes EmDash accepts, `zh-TW` and `zh-HK` included, written in that case
  - [x] one set of routes serves every language; `src/pages/th/` is deleted. Proof: 22 files
    under `src/pages` before, 12 after; `/ja/events`, `/ar/events`, `/th/events` and
    `/zh-TW/events` answer 200 with their own `lang`, `/xx/events` and `/en/events` answer 404.
    The language is one segment of the address (`src/pages/[...locale]/`). Astro's own
    `fallback` with `rewrite` was tried first and dropped: it answered `/about/fr` with the
    About page, and served the admin again under every language prefix
  - [x] right-to-left languages (Arabic, Persian, Urdu) render with `dir="rtl"`. Proof:
    `/ar/events`, `/fa/events` and `/ur/events` send `<html lang="…" dir="rtl">`; the rest `ltr`
  - [ ] every page carries `hreflang` links for the languages it exists in, and the sitemap lists
    them, the way EmDash's internationalisation guide shows
  - [x] the labels on event and organisation pages come from the app's own message catalogues
    where the app already has the words, not from a hand-written table. Proof: 21 of the 54
    labels are the app's, in each of the 26 other languages (`src/i18n/messages/<code>.json`;
    `src/i18n/ui.ts` says which key came from which). The other 33 show in English until a
    person who reads the language writes them: none was translated here
  - [ ] content is translated with the LinguaDash plugin from EmDash's registry, not by hand:
    installed in the local site, the target languages set, the translatable fields marked. Machine
    translations land as drafts; nothing unreviewed is published, and a page with no published
    translation shows English
  - [ ] the hostile privacy check passes again in three languages
